📋 Overview

Ethio Telecom RMS is a complete REST API for managing customer support tickets with real-time queue tracking, technician assignment, and appointment scheduling.

Key Features

  • Ticket Management - Customers report internet issues and get digital tickets
  • Live Queue Tracking - Real-time position, wait time, and queue ordering
  • Technician Assignment - Admins assign and manage technician workload
  • Appointments - Reserve support slots at branch offices
  • Service Reviews - Rate and review completed tickets
  • Notifications - Real-time updates on ticket status changes

Architecture

  • Backend: Next.js 15 (App Router)
  • Database: Neon Postgres (prod) / SQLite (dev)
  • ORM: Prisma
  • Auth: JWT (15m access + 30d rotating refresh)
  • Email: Resend (password reset)
  • Deployment: Vercel

🔐 Authentication

Access Token (15 minutes)
JWT sent in Authorization: Bearer <token> header. Short-lived for security.
Refresh Token (30 days)
Opaque token stored in DB. Rotated on every use (old token revoked). Single-use for added security.

Auth Flow

1. Register → get accessToken + refreshToken
2. Use accessToken for API requests (valid 15 min)
3. When accessToken expires:
   POST /api/auth/refresh with refreshToken
   → get new accessToken + new refreshToken (old revoked)
4. Logout: POST /api/auth/logout with refreshToken
   → token revoked, user must login again
Security Features:
• Password: bcrypt (10 rounds)
• Refresh tokens: SHA256 hashed, never returned after init
• Token rotation: old token invalid after refresh
• Session revocation: logout, password change, all revoke all sessions
• No leaks: passwords/hashes never in responses

📊 Queue System

Queue Ordering

Tickets ordered by:
1. Priority: URGENT > HIGH > MEDIUM > LOW
2. Within priority: FIFO (First-In-First-Out)
3. Status: OPEN, ASSIGNED, IN_PROGRESS (all counted)
         RESOLVED, CLOSED, CANCELLED (not in queue)

Queue Position

Field Meaning Example
position Your place in line (1-based) 5
ahead How many customers before you 4
estimatedWaitMinutes Estimated wait time 180 (3 hours)

ETA Calculation

estimatedWaitMinutes = ahead × AVG_HANDLE_MINUTES
where AVG_HANDLE_MINUTES = 45 (configurable)

Example: If you're position 5 with 4 ahead, and each ticket takes ~45 min, your ETA is ~180 minutes (3 hours).

🔌 API Endpoints

Authentication (10 endpoints)

POST /api/auth/register

Register new customer account, returns access + refresh tokens

POST /api/auth/login

Login with email/password, returns tokens

POST /api/auth/refresh

Exchange refresh token for new token pair (rotates)

POST /api/auth/logout

Revoke refresh token(s), supports logout everywhere

POST /api/auth/forgot-password

Request password reset, emails token via Resend

POST /api/auth/reset-password

Reset password with token, single-use

POST /api/auth/change-password

Change password while logged in

GET /api/auth/me

Get current user profile

PATCH /api/auth/me

Update profile (name/phone/email)

DELETE /api/auth/me

Delete account (blocked if tickets exist)

Tickets (9 endpoints)

POST /api/tickets

Report problem, get digital ticket

GET /api/tickets

List tickets (scoped by role: customer=own, tech=assigned, admin=all)

GET /api/tickets/:id

Ticket detail + live queue info

GET /api/tickets/:id/queue

Queue position, people ahead, ETA

PATCH /api/tickets/:id

Customer cancels or staff update status/priority

POST /api/tickets/:id/assign

Admin assigns technician (admin only)

POST /api/tickets/:id/resolve

Tech/admin mark ticket fixed

POST /api/tickets/:id/review

Customer rate service (closes ticket)

Appointments (3 endpoints)

POST /api/appointments

Reserve branch support slot

GET /api/appointments

List appointments (role-scoped)

PATCH /api/appointments/:id

Cancel (customer) or complete (staff)

Admin & Other (4 endpoints)

GET /api/technicians

List technicians + active workload (admin only)

GET /api/admin/queue

Full ordered queue for assignment (admin only)

GET /api/notifications

User notifications (supports ?unread=1)

GET /api/health

Health check

Total: 30 endpoints

⚙️ Setup & Deployment

Local Development

npm install
npm run db:push      # sync SQLite schema
npm run db:seed      # create test users (admin/tech/customer)
npm run dev          # http://localhost:3055
npm test             # run Playwright tests

Environment Variables

DATABASE_URL="file:./test.db"  (dev) or postgresql://...  (prod)
JWT_SECRET="your-64-char-random-secret"
EMAIL_FROM="noreply@theo.et"
APP_URL="https://your-domain.com"
RESEND_API_KEY="re_..."
REFRESH_TTL_DAYS=30
AVG_HANDLE_MINUTES=45

Deployment to Vercel

1. Link project: vercel link
2. Set environment: vercel env add
3. Deploy: vercel deploy --prod
4. Seed database (from Vercel CLI):
   npm run db:push  # sync schema
   npm run db:seed  # create test users

💡 Usage Examples

Register & Login

curl -X POST https://api.example.com/api/auth/register \
  -H 'Content-Type: application/json' \
  -d '{
    "name": "John Doe",
    "email": "john@example.com",
    "password": "secure123",
    "phone": "+251911000000"
  }'

# Response:
{
  "data": {
    "accessToken": "eyJ...",
    "refreshToken": "opaque-token",
    "user": {
      "id": "user-id",
      "name": "John Doe",
      "email": "john@example.com",
      "role": "CUSTOMER"
    }
  }
}

Report a Problem

curl -X POST https://api.example.com/api/tickets \
  -H 'Authorization: Bearer eyJ...' \
  -H 'Content-Type: application/json' \
  -d '{
    "subject": "No internet since morning",
    "serviceNumber": "0911-ETC-8842",
    "category": "NO_CONNECTION",
    "description": "Line dead, no connectivity",
    "priority": "HIGH"
  }'

# Response:
{
  "data": {
    "id": "ticket-id",
    "ticketNumber": "ETC-20260729-4821",
    "subject": "No internet since morning",
    "status": "OPEN",
    "createdAt": "2026-07-29T10:30:00.000Z"
  }
}

Check Queue Position

curl -X GET https://api.example.com/api/tickets/ticket-id/queue \
  -H 'Authorization: Bearer eyJ...'

# Response:
{
  "data": {
    "position": 5,
    "ahead": 4,
    "estimatedWaitMinutes": 180,
    "status": "OPEN"
  }
}

Refresh Token

curl -X POST https://api.example.com/api/auth/refresh \
  -H 'Content-Type: application/json' \
  -d '{"refreshToken": "opaque-token"}'

# Response:
{
  "data": {
    "accessToken": "new-jwt-token",
    "refreshToken": "new-opaque-token"
  }
}
